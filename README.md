# Unlock Bot

Unlock Bot позволяет сотрудникам разблокировать свою учётную запись Active
Directory через Telegram или MAX. Оба мессенджера обслуживаются одним набором
асинхронных обработчиков на базе
[`TelegramWithMax`](https://github.com/UselessHumster/TelegramWithMax).

## Возможности

- регистрация по рабочей почте с подтверждением администратора в Telegram;
- отдельные подтверждённые привязки Telegram и MAX к одному AD-профилю;
- разблокировка своей учётной записи любым текстом (или командой `/unlock`);
- привязка legacy-профиля через `/connect <логин>`;
- список заблокированных пользователей через `/status` для администратора.

После привязки обычный текст сначала проверяется как логин с доменами
`alkaloid.com.mk` и `alkaloid.ru`. Если такая учётка не найдена, разблокируется
закреплённая учётная запись. Исходное сообщение и результат отправляются в
Telegram-чат администраторов. Команда `/unlock` сразу разблокирует закреплённую
учётку; остальные команды сохраняют своё назначение. Текст существующего
пользователя без привязанной учётки проверяется по этим доменам. Первая учётка,
которую удалось разблокировать, автоматически закрепляется за ним.

## Установка и запуск

Проект рассчитан на Windows-хост с доступом к домену, PowerShell, `pyad` и
Windows API.

```bash
uv sync --frozen
uv run unlock_bot
```

Эквивалентный запуск:

```bash
uv run python -m unlock_bot.scripts.start
```

`TelegramWithMax` подключён из публичного GitHub по HTTPS и закреплён за
неизменяемым commit SHA версии `0.2.1`.

## Конфигурация

Создайте `.env`:

```env
BOT_TOKEN="TELEGRAM_BOT_TOKEN"
MAX_BOT_TOKEN="MAX_BOT_TOKEN"
DOMAINS="domain1.com;domain2.local"
SEARCH_ZONE="OU=Users,DC=example,DC=local"
ADMIN_CHAT="TELEGRAM_ADMIN_CHAT_ID"
DATABASE_PATH="C:/unlock_bot/data/unlock_bot.db"
BOT_PROXY="http://127.0.0.1:18080"
ADMIN_USER_IDS="123456789"
```

`ADMIN_CHAT` всегда относится к Telegram: туда приходят заявки и служебные
уведомления от пользователей обеих платформ.

`BOT_PROXY` необязателен и используется только для Telegram. `MAX_TOKEN`
поддерживается как альтернативное имя `MAX_BOT_TOKEN`. В групповом админ-чате
одобрять заявки могут пользователи с ролью `admin` в базе или Telegram ID из
`ADMIN_USER_IDS` (через запятую). В личном админ-чате — его владелец.

Вызовы AD выполняются последовательно в отдельном COM-потоке, оба бота работают
в одном event loop. Решения по регистрации записываются вместе с очередью
уведомлений; неудачная доставка повторяется каждые 30 секунд и после перезапуска.

MAX запускается через long polling. Перед запуском удалите активные webhook-
подписки; приложение обнаружит их и завершится с диагностической ошибкой.
Официально MAX рекомендует webhook для production, поэтому polling следует
считать осознанным эксплуатационным ограничением.

## Миграция данных

При первом запуске старая таблица `users` автоматически переносится в общую
модель AD-профилей и Telegram-идентичностей. Исходная таблица сохраняется под
именем `users_legacy`. Перед миграцией автоматически создаётся SQLite backup
`<DATABASE_PATH>.<timestamp>.bak`. Перенос выполняется транзакционно и повторяется
после сбоя. Старый код и конфигурацию также нужно сохранить до обновления.
